# Define content types and custom fields in code for v1

Built-in Posts and Projects can be extended with custom fields, and additional content types can be defined, through code configuration. Configuration changes require a restart or redeploy; the admin generates content-editing forms from those definitions rather than providing a visual schema builder.

This keeps v1 small while supporting portfolios with different content needs. Defining content types and fields through the admin UI is planned for the future, not part of v1.
